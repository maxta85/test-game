# artkit — the standards

This is the contract the rest of the game codes against. It is short on purpose: a
consumer should be able to read it, the palette table and the four batching rules,
and start placing things.

`artkit_check.gd` enforces the mechanical half of it. Run it:

```sh
godot --headless --audio-driver Dummy --path . --script res://artkit/artkit_check.gd
```

It exits 0 on pass, 1 on the first failing section, and prints a summary of
measured draw calls and triangle counts so the numbers here can be checked
against reality rather than believed.

---

## 1. What this is

A procedural asset library. Every mesh in it is generated by GDScript at
load time from a seed. There is no `.glb`, no `.obj`, no downloaded texture, no
`.png`. That is a hard constraint from the brief, and it is also what makes the
whole city affordable: 2198 buildings, ~1600 palms and ~1300 streetlights cost
nothing to store and everything to draw.

The consequence is that **consistency is not a style guide here, it is a
mechanism.** A colour nobody chose, a material that is equal-by-value rather than
the same instance, or a mesh that gets `duplicate()`d per instance will all
produce something that still renders. The frame rate is the only symptom. So the
rules below are checked, not documented-and-hoped-for.

## 2. The files

| File | What it owns |
|---|---|
| `palette.gd` | every colour in the game, as named roles. The only file allowed to contain a hex literal. |
| `mesh_kit.gd` | primitive builders. No colour, no material, no object semantics. |
| `materials.gd` | material instances, one per key, cached forever. Procedural noise textures. |
| `part.gd` | one drawable piece: a mesh plus a material key. |
| `batch.gd` | the MultiMesh collapser. Turns parts into draw calls. |
| `props.gd` | street furniture and vegetation. |
| `buildings.gd` | buildings, including the wrapper for the 2198 real OSM footprints. |
| `artkit_check.gd` | this document's enforceable claims. 78 checks. |

## 3. Units, axes, origin

- **1 unit = 1 metre.** Storey is 3.0 m. Sill is 0.95 m. A door head is 2.05 m.
  A streetlight column is 7.2 m. These are `const` in the files that use them and
  the check asserts the two files agree.
- **+Y up, +Z forward** (the direction a prop faces), +X right.
- **Origin at the footprint centre, on the ground.** Every generator returns
  geometry whose local origin is where the object stands. So placement is a
  position and a yaw with no correction offset, via `ArtKitBatch.place()`.
- **Uniform instance scale only.** `ArtKitBatch` does not normalise transforms,
  and a non-uniform scale shears the normals of an already-baked mesh. Height
  variation is therefore uniform instance scale via `ArtKitBatch.place()`, never a
  baked parameter — a baked height is a different mesh and a different draw call.
- **Three kinds of prop, and the registry says which.** A prop either stands on
  `y = 0`, sinks at or below grade (`"sink": true` — scrub, grass, open drains,
  wire spans), or hangs at bracket height against a wall (`"mounted": true` — the
  wall bracket and the illuminated sign box). The check enforces the right one per
  kind, so "floats above the footpath" is a test failure and not a render
  surprise.

## 4. The palette

### 4.1 The rule

> Saturated colour is a light source, not a surface.

`artkit_check.gd` enforces this literally: it walks `ArtKitPalette.ROLES`, and any
role that is not marked `"emits"` must have HSV saturation at or below
`SURFACE_SATURATION_MAX` (0.22). A wall that wants to read as cream gets a dark
warm neutral and lets the sodium lamp supply the hue. Paint it cream in the
albedo and it is a flat grey block by day and a blown-out orange slab by night —
both wrong.

This is why the surface roles occupy a narrow dark band and why the entire
saturation budget is spent on lamps and glass.

### 4.2 The nine light roles come from the doc, not from taste

`Base night`, `City glow`, `Sodium`, `Mercury / shopfront`, the three `Neon
accents`, `Tail lights` and `Headlights` are lifted verbatim from the palette
table in `ART_DIRECTION.md`. The check parses that table out of the markdown at
run time and fails if a hex or a label drifts. The doc is the source of truth; if
you need a new colour, add a row to the doc first.

### 4.3 Every role needs a `use`

A role with an empty `use` string is a role that will be placed at random. The
check rejects one. There is no such thing as a spare colour in this palette.

## 5. Materials

One `StandardMaterial3D` per key, built once, cached in `ArtKitMaterials`, and
shared by reference forever. `get_()` returns the same object for the same key
for the life of the process.

- Every key's albedo is a palette role. No key holds a hex.
- A material with emission energy above zero names its `emit_role`, and that role
  must be a light role. An emissive material whose colour nobody chose is how a
  street ends up orange.
- Families carry the variation: six rendered walls, five roof-iron values, four
  asphalt values, four foliage values. Variation is achieved by *mesh* variant
  and *material* variant, deliberately not by per-instance colour — a MultiMesh
  custom-data path would need a shader variant and a uniform upload per material
  and is not worth it at this object count.
- **The hero surface is the road.** `surface_asphalt_wet_a..d` carry a procedural
  *roughness texture* ramping inside 0.10–0.18, at `metallic_specular` 1.0 and
  `metallic` 0 — a dielectric with a broken-up roughness, which is what makes
  reflections streak down the tarmac instead of reading as a sheet of plastic. A
  scalar roughness would give every road in the city the same mirror.
  `surface_asphalt_dry` is 0.74 for the verges. If a render has no long vertical
  smears of light down the tarmac, it is not finished.
- Foliage is two-sided and self-lit at ≤ 0.10 energy, so a streetlight behind a
  frond bleeds through it. Above that a frond stops being a leaf and starts being
  a light box.

## 6. Batching — the four rules a caller can break

1. **Share meshes, do not copy them.** `part.mesh.duplicate()` per instance makes
   the signatures differ and the batching silently collapses to one draw call per
   instance. Nothing warns you.
2. **Take materials from `ArtKitMaterials.get_()`.** Two equal-by-value materials
   are two draw calls.
3. **Uniform instance scale only.** See §3.
4. **One material per part.** Generators call `ArtKitPart.weld()`, which merges
   same-material parts into one mesh and drops empty ones, so a returned array
   has exactly one entry per distinct material. The check asserts
   `parts.size() == distinct material count` for all 26 props and 5 buildings,
   because a generator that quietly returns two parts in the same material is a
   generator that doubled one building's draw calls.

`ArtKitBatch.build()` emits one `MultiMeshInstance3D` per (mesh, material) group
under one parent, sets `custom_aabb` from the collected transforms (without it
a MultiMesh is culled against the first instance's box, which is how a suburb
vanishes when you turn away from one particular house), and sets
`material_override` because the shared meshes carry no surface material.

### Two strategies, and which one you want

- **`build()` — instancing**, for anything repeated. Meshes must be shared
  resources, which is why every generator is memoised and why `variant()` is the
  front door. Measured: the whole prop set placed 1650 times comes to **126 draw
  calls for 3150 instances**, and 1300 streetlights come to **2**.
- **`build_merged()` — baking**, for anything unique, which includes all 2198 OSM
  footprints because every one of them is a different mesh. Measured: 400 unique
  wrapped footprints bake to **15 draw calls** — 6 wall colours + 5 roof colours +
  concrete + dark glass + lit glass + interior glow. The draw call count is the
  size of the *palette*, not the size of the city.

Instancing is the right instinct and it is the wrong tool for a footprint that
was measured off OpenStreetMap. Both numbers above come out of the check.

### Shared meshes are not optional

Calling a generator in a loop returns a *new* mesh every call, every signature is
unique, and batching silently collapses to one draw call per instance. Nothing
errors; the frame rate is the only symptom. So every generator is memoised by
recipe, and `ArtKitProps.variant(name, i)` / `ArtKitBuildings.variant(name, i)`
are the documented front doors. The check asserts both the sharing and that two
variants are genuinely different meshes, because a cache that returns the same
mesh for every variant would pass a naive sharing test and render one tree 1600
times.

## 8. The OSM path

`ArtKitBuildings.wrap_footprint()` exists so the 2198 real footprints get the art
direction without being rewritten. It takes the real polygon and gives it a 0.3 m
plinth, a recessed wall extrusion, gabled or parapeted roof by width, and real
window openings in a bay rhythm on the −Z face, with the lit/unlit mix at
`lit_ratio` (default 0.4 — a suburb where every window is lit is a suburb with
nobody home, and it destroys the only reason lit windows exist).

The caller supplies the yaw, because only the caller knows which way the street
faces.

## 9. Known gaps

Listed rather than quietly shipped.

- **Window openings are not cut through the extruded prism.** The walls are
  extruded from the footprint scaled in by half a wall thickness and the window
  wall is built in the gap, which is exact on the extreme faces of a straight
  footprint and drifts a couple of centimetres at the corners of an L-shaped
  one. A true polygon offset with self-intersection removal is more code than the
  artefact is worth at this point.
- **No LOD, no occlusion culling, no light culling, no spatial partitioning.** A
  MultiMesh is one draw call for the batch, so culling would have to split batches
  to pay off, and splitting per district is a bigger win than per-object LOD at
  this count.
- **No per-instance colour.** See §5.
- **No vehicles, no pedestrians, no road surface.** Those are other briefs; this
  kit supplies the asphalt materials and nothing else.
- **`artkit_check.gd` reads `ART_DIRECTION.md` from `res://`.** Fine in the
  editor and in headless runs; if this ever needs to run from an exported PCK,
  the doc has to be added to the export filter first.
